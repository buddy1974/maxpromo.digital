## Why WordPress Gets Stuck in Maintenance Mode

During a WordPress update — core, theme, or plugin — the system creates a file called `.maintenance` in the root directory. This file signals that maintenance is in progress. Normally WordPress deletes this file automatically when the update completes.

If the update breaks mid-process — due to a PHP timeout, a server error, or a plugin conflict — the `.maintenance` file stays put. WordPress then shows every visitor the maintenance page: "Briefly unavailable for scheduled maintenance. Check back in a minute."

That sounds harmless. If nobody notices, the site can be down for hours or even days.

## How to Fix It

**Fastest fix:** Connect to the server via FTP or SFTP. In the WordPress root directory you'll find a file called `.maintenance`. Delete it. The site is immediately accessible again.

If you don't have FTP access: most hosting control panels — Hostinger, GoDaddy, A2 Hosting — have a built-in file manager that does the same thing.

## Why It's Still a Warning Signal

The symptom is quick to fix. The underlying problem — why the update broke in the first place — remains.

Common causes of broken WordPress updates:

- PHP memory limit too low (typical on cheap shared hosting packages)
- Plugin conflict throwing a fatal error during the update process
- Database connection error mid-update
- Server timeout during large updates

We've taken over installations where this happened multiple times per month — because nobody had addressed the root cause.

## What This Has to Do With the Bigger Picture

WordPress installations that regularly fall into broken states are usually installations that have grown over years without structured maintenance: too many plugins, outdated PHP version, no backup process.

That's fixable — either through cleanup and structured maintenance, or in more advanced cases through migration to a platform that structurally doesn't have these problems.
