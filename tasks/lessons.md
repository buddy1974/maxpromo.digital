# Engineering lessons

- A UI example is not a wire fixture. A real rejection reason proves only its exact guard:
  invalid_event_id does not distinguish empty IDs from forbidden characters. Emit bounded
  known-field structural metadata, never values/arbitrary key names, before inventing a
  dynamic provider-Test discriminator or broadening acceptance.

- Distinguish payload mailbox validation from database account lookup. A wrong_mailbox400
  can reject the provider's synthetic sample before getDb. Prove exact fixture incompatibilities
  locally; acknowledge only the complete evidenced connectivity fixture with zero side effects.

- Webhook readiness probes cannot certify a provider's Test payload contract. Preserve
  safe fixed rejection stage/reason codes (never bodies, URLs, secrets or raw exceptions)
  so a genuine authenticated400 can be traced without weakening validation.

- Environment-only production releases need a new deployment after secret installation.
  A Git redeploy can intentionally cancel on the unchanged-app ignore rule; inspect the
  actual log and use the established CLI release path, preserving permanent ignore logic.

- PostgreSQL data-modifying CTEs share a snapshot: do not UPDATE a row inserted
  by a sibling CTE through a table scan. Return needed identities or perform an
  idempotent follow-up metadata repair. Verify concurrency against real isolated SQL.
- Keep transport uncertainty distinct from failure; a timeout must never trigger a blind resend.
- Inbox Tailwind utilities contribute to shared CSS; reuse existing controls and keep budgets unchanged.
- Treat delivery IDs, provider message IDs and RFC Message-ID headers as distinct identities.
  Preserve opaque ID case; an example hex/UUID shape is not an undocumented provider guarantee.
- Webhook text previews must not silently become full-body context. Signed URLs require verified
  host/media policy and pinned DNS, not just HTTPS or a provider-authenticated envelope.
- A locked deployed receiver should reject missing credentials without reporting a service
  outage. Conditional release authorization does not waive required model-backed checks.
- Vercel env run may export empty production secrets and overlay local dotenv values.
  Never label that fallback as current-production-key proof. Keep non-exportable model
  credentials in-cloud and isolate a build child against evidence data for certification.

- Read the diagnostics you deployed before asking for another owner test: the answer to
  "what is eventId on the wire" sat in Vercel logs from two retries nobody recorded.
- Do not impose a grammar on provider-owned opaque ids, and do not 400 an authenticated
  provider over content quirks: refusal loses mail and auto-pauses the webhook.
- A bypass keyed to documentation examples is overfitted; check it against real traffic.
- Owner-sent proof mail rarely matches the plan (this one carried a PDF). Design the receiver
  so unplanned content degrades to safe metadata instead of needing a new test.
- Before claiming "Leads" visibility, read the filter: it means an owner-confirmed CRM link,
  not the triage classification.
- A sealed-locator length is evidence without exposure: 1,688 ciphertext chars proved real
  signed URLs arrived and were sealed, without revealing a single URL.
- A gate fix applied to one app and "deliberately left" for the other is a scheduled incident:
  the Bureau's old ignore rule silently kept a critical security fix out of production for weeks.
- Source-pattern proofs pin implementations, not guarantees. When an invariant gets stronger
  (email from the stored record), update the proof to the stronger invariant, not the old string.
- jsonb reorders keys: never compare stored engine answers by serialised JSON, and never rely
  on jsonb for display order.
- Python heredocs turn "\n" in embedded JS into real newlines; edit code with the Edit tool,
  not string-substituting scripts, when the payload contains escapes.
- Before any release push, compare every app's pending migrations with its production schema.
  The OS migrations were applied; the Bureau's were "deferred to the EU move" and would have
  broken the Bureau on release.
- A provider webhook is not the provider's state. Hostinger fires `message.received` for Junk mail
  and sends no folder; spam state has to be read where it lives (the folder API).
- Count unknown payload keys on accepted events, not only rejected ones, so a contract change
  becomes visible without logging values.
- This session's permission policy allows additive schema SQL only sometimes and never data
  corrections or secret-store writes; plan those as owner steps with exact SQL and verification.
